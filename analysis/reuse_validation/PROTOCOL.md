# RoleMap: retrospective validation of role-conditioned allocation

## Purpose and scope
Strengthen the existing WWW Resource paper by showing a concrete use of its linked task observations and SID groups: decide whether pooling the observed member allocations across search and recommendation loses reproducible information. This evaluates an analysis choice, not a new recommender, causal semantic conflict, ranking improvement, or a static representative action. The historical Qilin test and common-item cohort have been used before; call this retrospective temporal validation, never untouched confirmation.

## Runtime and authorization
Fit closed-form categorical distributions locally, without neural training or model calls. Provider extraction and scoring use a separately declared runtime. Keep all generated provider-derived rows and fitted probabilities outside the source checkout.

## Input identity and units
Use original Qilin provider train/test Parquet files with the four known SHA256 bindings from the prior extraction. Reuse strict request intervals: train end <1732700625; validation start >=1732700625 and end <1732706088; provider test is historical test. Record ranges and verify no temporal overlap. Export every valid request with catalog exposure, not only positive targets. Keep only hashed user/request identifiers, times, distinct valid exposed item IDs and distinct clicked item IDs in restricted files; no query/history/text. Deduplicate members within each request. Invalid/missing timestamps and crossing intervals are excluded and counted.

Use the frozen 20,540-item common cohort solely as an explicit historical resource cohort; it was selected using pooled observations and is not an unbiased prospective catalog population. Codes were produced by actual native components on declared features, not full-system reproductions. Primary grouping: GenSAR shared two-token prefix. Verify the two native complete views have identical first two tokens for every item. Secondary: GenSAR semantic complete view, collaborative complete view, GAOQ depth1/depth2/full3. They are different granularities/views, not independent algorithm families. Do not compare raw losses across granularities as method quality. GAOQ full-code uniqueness is a no-collision control and need not produce an artificial inferential endpoint.

For each map, a scored request contains at least one mapped exposure in a catalog collision group (group size>1). Average log loss equally across its distinct collision groups, and within each group equally across its distinct exposed members. This is a request-conditional exposure-allocation estimand; it is not the distribution of clicks or user relevance. Train categorical counts use the same 1/(number of exposed collision groups * exposed members within group) weights. Keep groups with zero or one-role train support and let priors handle them. Report all source/mapped/scored request counts, train supported groups, unseen groups/members, and singleton coverage. No fixed per-item minimum-count gate.

## Primary common-time audit partition (metadata-driven revision before any outcome fitting)
Official test calendars do not overlap between roles (recommendation1732706088..1732723187, search1732735658..1732752025). Therefore the shared validation interval1732700625..1732706088 is partitioned by user before fitting: compute SHA256 UTF-8 bytes of literal salt `rolemap-allocation-val-v1|` concatenated with the existing hexadecimal user_hash; interpret the first16 lowercase hex characters as an unsigned big-endian64-bit integer and take modulo2. Remainder0 is tuning (`validation.jsonl`, split=validation), remainder1 is the primary audit (`audit.jsonl`, split=audit). This fixed literal salt is the sole partition rule; the bootstrap seed does not enter partitioning. Both role records of a user always stay together. Both partitions retain `source_chronological_split=validation`. Export metadata may count them before fitting; only tuning exposures enter selection. The fit process never opens audit.jsonl. Audit users are disjoint from tuning users, but may occur in train; this is longitudinal forecasting, not new-user generalization. Historical official test remains a secondary schedule/provider-conditional transport check and cannot replace the primary. Shared calendar envelope does not identify a causal role effect independent of time.

## Models and validation selection
Each collision group has a uniform positive prior over all its catalog-cohort members. Alpha grid {0.1,1,10,100,1000} is fixed before outcomes.
Pooled: (c_search+c_rec+alpha*u)/(n_search+n_rec+alpha).
Balanced pooled: reweight each role's train request contributions to equal role mass while retaining total effective count: for each map N_r is its number of scored training requests (sum of fractional count mass), a_r=(N_search+N_rec)/(2*N_r), and each role count is multiplied by a_r. Then use the same formula/grid. Select the stronger roleblind model and alpha by validation macro-role request log loss (natural log), with deterministic ties favoring pooled then smaller alpha.
Separate: (c_role+alpha*u)/(n_role+alpha), one shared alpha for both roles selected independently for this strategy by macro-role tuning loss.
Shrinkage: (c_role+beta*p_pooled)/(n_role+beta), one shared beta for both roles in {0.1,1,10,100,1000}; p_pooled is the selected pooled predictor. Include the selected pooled model itself as the infinite-shrinkage option. Select one role-aware strategy (separate/shrinkage/pooled fallback) by validation macro-role loss; ties favor simpler pooled, then larger shrinkage, then separate. Freeze before reading audit or historical test. Report every strategy's validation score and selected hyperparameters.

## Endpoints and uncertainty
Primary: selected roleblind minus selected role-aware primary audit log loss, macro-averaged over the two roles, on the GenSAR shared2 grouping. Positive values indicate improved forecast of future exposed-member allocations when retaining role. Report each role, absolute loss, difference in nats per scored request, coverage and a paired user-cluster bootstrap 95% interval (2000 draws, seed20261019). Resample the union of audit users (or historical-test users for its separate transport report), preserving both roles and all of each user's scored requests; compute macro-role means on each draw. These are conditional intervals for the fixed maps/protocol, not map-training variability. Evaluation bootstrap never tunes models. Secondary views are descriptive sensitivity, not independent replications or automatic pass gates.

Prespecified robustness: repeat the training fit using only the overlap of role-specific training time ranges, with the same tuning/audit/historical-test rows and model grid. Strategy and hyperparameters are reselected on tuning users only for this sensitivity, then frozen before audit. Primary exact weights remain unchanged in definition. Context-label forecasts and RSD-based prioritization are outside this experiment; no target is defined using RSD/RSI. The earlier click-representative null result remains recorded and is not overwritten.

## Result-to-claim rules
Positive primary estimate with interval above zero: role-conditioned allocation carries reproducible temporal information on this declared cohort and exposure estimand; useful evidence for a concrete resource workflow. Report the common-training-window estimate and interval alongside it, describing sign agreement or timing sensitivity without an additional binary pass gate. No ranking/semantic-conflict/model superiority claim.
Inconclusive or pooled selected: temporal utility not established for this workflow; retain descriptive comparisons and diagnose coverage/uncertainty rather than tuning thresholds to obtain a pass.
Opposite roles or sensitive overlap-window result: report heterogeneity and timing dependence, no universal role effect. Large secondary-only gain cannot replace the primary after outcomes.

## Validation and reporting
Before real fit: synthetic tests for request balancing, priors/zero support, exact probability normalization, role-label swap invariance, no-collision control, user-cluster dependence, deterministic validation selection, and train/test phase separation. Independent review checks protocol and implementation before audit/test evaluation. Output aggregate CSV/JSON and a readable scientific interpretation; restricted row-level scores stay local. New author draft/release integration occurs only after result review and separately versioned manuscript work.
