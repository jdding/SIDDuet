# Additional shared-calendar audit

This protocol is fixed after coverage inspection and before any new fit or loss computation. The data are historical and partly overlap the source period of a prior disjoint-calendar transport check; this is a new shared-calendar analysis, not an untouched external confirmation.

The 144,768 valid provider requests were scanned only for time, identity and exposure coverage. The unique contiguous run of complete 30-minute bins after the original audit is 2024-11-27 11:30:00 through 15:30:00 UTC, eight bins. Use the entire run as a half-open interval [start,end). No prediction, loss, label-divergence score, click or outcome direction selected the interval. The coverage scan and WINDOW.json are frozen alongside this protocol. No alternate window is to be selected after seeing losses.

Use the fixed 20,540-item historical cohort and all six shipped GenSAR/GAOQ views. GenSAR's common two-token prefix remains the designated primary; the other four estimable views are secondary and GAOQ full codes remain a no-collision control. Existing item mappings, smoothing grid, request weighting, task-balanced macro loss and deterministic estimator selection remain byte-identical. No threshold, bucket definition or quantizer is changed.

Training uses complete valid requests ending before the new interval. Requests wholly inside the interval are assigned jointly across tasks by the original fixed user-hash rule to tuning or audit. Requests crossing either boundary are excluded rather than truncated. A provider train/test label is provenance, not the new chronological split. The source files are combined for a retrospective chronological comparison; no claim is made about the provider's official benchmark split. Earlier training may contain tuning or audit users; tuning and audit users are disjoint. The fitting command must not open audit losses or audit rows. Freeze its receipt and probabilities before evaluation.

The primary endpoint is selected task-blind minus selected task-conditioned macro exposure-allocation log loss in nats. Report both task means, macro means, coverage and paired user-cluster 95% intervals, using the unchanged 2,000-draw engine and seed 20261019. Refit only the existing count estimators on the new earlier data. This is not recommender or quantizer training.

For multiplicity, report per-window five-view 99% percentile intervals targeting nominal 95% family coverage. Also report a conservative ten-endpoint sensitivity spanning the original and new windows, each with 99.5% marginal intervals, targeting nominal 95% family coverage. Extend the same sorted-user random streams to 40,000 draws; require exact reconstruction of the original 2,000-draw intervals within 1e-12. The paired bootstrap retains each user's observations from both tasks. Bonferroni does not require independence among windows or views; percentile bootstrap coverage remains approximate and conditional on fixed maps, fits and cohorts. More draws add no observations. Never replace the primary with a surviving secondary view. No significance threshold is a resource-admission gate.

Publish complete aggregate estimates and intervals regardless of sign. Same direction with broad intervals gives limited stability evidence; direction changes or selective-view gains support context-specific use, not universal task conditioning. This experiment does not validate RSD/RSI, semantic incompatibility, causal interference or ranking improvement. Source Parquet, request/user rows, fitted member probabilities and request losses remain local.

Runtime: local CPU; no neural/API calls, no GPU or paid services. The coverage parser took about 14 seconds. Budget at most 20 CPU minutes for fitting, scores and all bootstrap sensitivities; record actual timing and code/input hashes. Selective local receipts are used directly; no remote transfer or post-run pullback applies.
