# Population checks, score ties, and numerical cuts

These are the original 199-draw records. The [1999-draw extension](../diagnostics_mc1999_20261020/README.md) provides the current higher-precision comparison; original files remain unchanged for reconstruction.

These aggregates address two questions about the fixed RoleMap resource: whether the selected collision example represents the supplied mappings, and why the label-based scores form large ties. A supplementary exact-total reference and a cut sensitivity study follow the primary analysis. The existing `sr_sid_rolemap.topology.value_median.v2` reference is unchanged.

The scope is 97,729 KuaiSAR and 20,540 Qilin common items, joined to three existing supplied mappings: GRID, RQ-VAE and ReSID-GAOQ. No mapping was fitted and no model was trained for these checks. The outputs do not establish independent external adoption or predictive benefit.

## Do collision groups separate the sources of task observations?

Within each complete SID group, member-allocation JSD compares the search and recommendation count distributions **over its members**. This is different from item-level divergence between provider-label distributions. Singleton groups remain in coverage accounting and are excluded from collision-group summaries. The primary mean weights collision groups equally; item- and observation-weighted means are secondary.

The original paired-regrouping reference permutes each item's positive `(search, recommendation)` count pair among fixed group slots within floor-log2 total-support bands. It preserves group sizes, each slot's support band and the global paired-count multiset. The post-primary exact-total reference instead permits exchanges only between slots with the same exact total support, preserving the entire total-support vector of each group. Separate group search/rec totals can change under both references. Both use 199 permutations, with the same dataset draw shared across mapping families.

All six actual equal-group JSD means are lower than both references. The narrow conclusion is an association: these supplied groups have more similar observed task-allocation ratios than the stated count-matched regroupings. This does not isolate a causal effect of semantic IDs, show semantic compatibility, or prove freedom from model harm. The Qilin/ReSID-GAOQ comparison concerns only 251 collision items, 1.22% of its common-item universe; its conditional result is not broad population coverage.

The fixed 275-item demonstration is around the 99.67th percentile of JSD within its own collision-group population. It illustrates a possible pattern and should not establish prevalence. Leader-set measures also differ from full-distribution JSD: for example, the exact-total comparison has a positive item-weighted disjoint-leader difference on KuaiSAR/GRID (+0.009516), despite its negative JSD contrasts. All secondary measures and denominators are retained.

The original finite-count hypergeometric reference fixes each member's combined count and group task totals but permits zero simulated task counts. The observed common-item universe requires positive counts for both tasks. This reference therefore does **not** provide a selection-matched noise correction, even though its stated marginals were checked exactly. The exact-total supplement addresses a different regrouping question and does not remove this caveat.

The primary and supplementary six-comparison families are separate. Their Monte Carlo tail values have resolution limited by 199 draws; the exact-total analysis was designed after the primary outcomes were inspected. The exact-total supplement uses the same underlying inputs and is not an independent replication of the primary result. The shipped results retain weighting schemes, fixed strata, multiplicities, null summaries and negative findings. Complete simulation draws are generated by the analysis scripts and kept outside the source checkout.

## Why do the label scores tie?

The maximum-RSD tie is exactly the cohort whose observed search/rec label sets are disjoint: 65,354/97,729 KuaiSAR items and 14,884/20,540 Qilin items. These observations saturate all three declared components at 1. Their raw JS values are already exactly 1; no endpoint Q12 merge creates that plateau, and no different component triple collides to the same exact RSD fraction. Interior binary64-to-Q12 merges remain reported separately.

The maximum tie contains minimum task support = 1 for 82.95% and 90.08% of its items, respectively. This is an association with sparse observed support, not an identified behavioral cause. In particular, differing single labels give two zero entropies and RSI = 0 while label JS = 1. Equal entropy is not evidence of agreement between labels. Provider labels describe contextual observations; these checks do not establish semantic incompatibility, human preference differences or model failure.

The complete tie summaries, source-support checks, label-regime partitions, component triples and raw/key merge tables are under `ties/`. Item-level IDs, label joins and source counts are excluded.

## Can changing the cuts populate four cells?

The supplementary cut study reports every pair from q_RSD, q_absolute_RSI in {.25, .50, .75}, preserving every equality block. The .50 cut is the exact ordinary median used by v2; .25/.75 use nearest rank. All items at a cut remain on its L side. Each dataset's nine labels collapse to four distinct cut pairs. Four cells appear for one KuaiSAR combination and two duplicate Qilin combinations, so the median-specific empty high region is not a universal impossibility.

An exhaustive descriptive scan over all numerical-cut partition classes finds that the largest attainable smallest cell contains 9,907/97,729 (10.14%) items on KuaiSAR and 2,828/20,540 (13.77%) on Qilin. Every maximizing cut class is retained. At the Qilin representative, the entire high-RSD side still contains only the single maximum RSD value; KuaiSAR also retains single-value cell coordinates. Populating cells redistributes existing atomic blocks and does not create information within them. No alternative is selected as a replacement protocol and no utility is inferred from occupancy. See `thresholds/` for every declared combination and all maximizing intervals.

## Files and reuse

- `population/`: primary population results and null summaries.
- `exact_total/`: separately labelled post-primary exact-total results and compact comparison table.
- `ties/`: both datasets' numerical decompositions and support/label summaries, with a compact table.
- `thresholds/`: both datasets' nine-pair summaries, all maximizing cut classes and the complete eighteen-row table.
- `EXPORT_PROVENANCE.json`: original and exported file hashes, the exact transformation and value-preservation checks.

Use the files to inspect a declared diagnostic or test an alternative interpretation of these fixed observations. The frozen source and research protocols are in [analysis/diagnostic_extension_20261019](../../analysis/diagnostic_extension_20261019/README.md), which documents synthetic checks and the lawful-input requirements for real replay. The release's main quickstart remains a synthetic interface check; it does not rebuild every real mapping or regenerate these population results.

Four JSON files replace only the original local project absolute path prefix with `<local-project>`. Every numerical value, other string and embedded hash is preserved. Original execution hashes still identify the original local files; redacted exports have their own hashes in `EXPORT_PROVENANCE.json`. They are not represented as byte-identical copies. These receipts record the original executions and are not portable real-run commands or substitute acceptance gates.

The public source checkout omits machine-specific execution receipts and full simulation draws. Original study hashes remain provenance; the optional public CLI does not require the author workflow's approval receipts.
